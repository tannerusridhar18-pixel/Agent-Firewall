# V0.4 Security Controls & Defense Matrix

V0.4 implements comprehensive runtime security controls across the IntentGuard MCP Gateway:
1. **Provenance & Sensitivity Propagation**: Ingestion, tracking, and fail-closed validation of untrusted inputs.
2. **Contextual Categorical Risk Evaluation**: Deterministic `LOW`/`MEDIUM`/`HIGH`/`CRITICAL` risk classification with explainable factors.
3. **Approval Workflows**: First-class `REQUIRE_APPROVAL` lifecycle with atomic, single-use `Approval` tokens and replay prevention.
4. **Session Quarantine**: Immediate session isolation for high-risk or repeat violations (default threshold: 3 hard denials).
5. **Fail-Closed Audit & Evidence**: Unforgeable cryptographic argument hashes, provenance refs, and fail-closed persistence aborting execution on storage failure.
6. **Bypass Defenses & Credential Isolation**: Downstream tools executed exclusively via protected gateway context.

## Gateway Enforcement Pipeline (Authoritative Sequence)

Every protected call received at `POST /mcp` undergoes an 8-gate fail-closed sequence:

```
AI Agent / MCP Client
   │  Headers: Mcp-Session-Id, X-IntentGuard-Capability, [X-IntentGuard-Approval]
   │  JSON-RPC: {"method": "tools/call", "params": {"name": "...", "arguments": {...}, "provenanceRefs": [...]}}
   ▼
┌────────────────────────────────────────────────────────────────────────────────────────┐
│                        INTENTGUARD MCP GATEWAY (/mcp)                                  │
├────────────────────────────────────────────────────────────────────────────────────────┤
│ Gate 1: Session Status & Quarantine Check (SessionRepository + QuarantineService)      │
│         - Fails if session != ACTIVE or QUARANTINED (Reason: SESSION_QUARANTINED)       │
│                                                                                        │
│ Gate 2: Capability Validation (CapabilityService)                                      │
│         - Token hash, unexpired, unrevoked, task match, tool match, resource scope     │
│         - MANDATORY BEFORE TOOL LOOKUP                                                 │
│                                                                                        │
│ Gate 3: Tool Manifest & Argument Normalization (McpToolRegistry)                       │
│         - Verified manifest metadata: sideEffect, riskLevel, destinationConstraints    │
│                                                                                        │
│ Gate 4: Provenance Resolution (ProvenanceService)                                      │
│         - Validates provenanceRefs; tags arguments with trust level & sensitivity      │
│         - Unknown reference fails closed (INVALID_PROVENANCE_REF)                      │
│         - Untrusted provenance to restricted operations denied (UNTRUSTED_PROVENANCE)  │
│                                                                                        │
│ Gate 5: Policy & Risk Evaluation (PolicyEngine + RiskEvaluator)                         │
│         - Computes RiskSnapshot (categorical level + explainable factors)              │
│         - Hard contract violations produce immediate DENY                              │
│         - High-risk operations escalate to REQUIRE_APPROVAL                            │
│                                                                                        │
│ Gate 6: Approval Resolution (ApprovalService)                                         │
│         - If REQUIRE_APPROVAL without valid approval token:                            │
│             Mints pending Approval record, returns REQUIRE_APPROVAL, executes 0 times  │
│         - If resuming with X-IntentGuard-Approval:                                     │
│             Validates matching task, session, tool, canonical argument hash           │
│             Consumes approval atomically (single-use); replay/expiry fails closed      │
│                                                                                        │
│ Gate 7: Fail-Closed Audit & Evidence Persistence (AuditService)                        │
│         - Persists SecurityDecision & ActivityEvent with arguments hash & provenance    │
│         - If persistence fails, halts execution immediately (SEC-012)                  │
│                                                                                        │
│ Gate 8: Protected Tool Execution (ProtectedTool)                                       │
│         - Executes downstream tool exactly once in isolated context                    │
└────────────────────────────────────────────────────────────────────────────────────────┘
```

## Control-Plane APIs

All operator endpoints require:
- `X-IntentGuard-Operator-Key`: Shared secret configured via `intentguard.control-plane.api-key`.
- `X-Operator-Id`: Identity of the operator or service.

### 1. Approvals API
- `POST /api/v1/approvals/{requestId}/approve` — Approves pending request.
- `POST /api/v1/approvals/{requestId}/deny` — Denies pending request.
- `GET /api/v1/approvals/{requestId}` — Inspects approval details and status.

### 2. Session Quarantine API
- `POST /api/v1/sessions/{sessionId}/quarantine` — Manually isolates a session.
- `POST /api/v1/sessions/{sessionId}/unquarantine` — Releases a session from quarantine.
- `GET /api/v1/sessions/{sessionId}/quarantine` — Retrieves active quarantine record.

### 3. Decision Evidence & Audit API
- `GET /api/v1/audit/{requestId}` — Retrieves the full cryptographic evidence record.
- `GET /api/v1/security-events` — Retrieves security events stream.

| Test ID | Scenario | Expected Outcome | Verified |
|---|---|---|---|
| `SEC-001` | In-scope allowed tool with valid capability | `ALLOW`, executes once | YES |
| `SEC-002` | Unknown tool | Protocol error, 0 executions | YES |
| `SEC-003` | Tool outside task scope | `DENY`, 0 executions | YES |
| `SEC-004` | Argument violates resource contract | `DENY`, 0 executions | YES |
| `SEC-005` | Parameter smuggling (path traversal) | `DENY`, 0 executions | YES |
| `SEC-006` | Untrusted provenance to restricted destination | `DENY`, 0 executions | YES |
| `SEC-007` | Expired approval token | `DENY`, 0 executions | YES |
| `SEC-008` | Replayed approval token (already consumed) | `DENY`, 0 executions | YES |
| `SEC-009` | Quarantined session attempting execution | `DENY`, 0 executions | YES |
| `SEC-010` | Capability cross-session / cross-task confusion | `DENY`, 0 executions | YES |
| `SEC-011` | Unknown / corrupted provenance reference | Fail closed (`INVALID_PROVENANCE_REF`), 0 executions | YES |
| `SEC-012` | Audit persistence failure | Aborts execution before tool call | YES |
