# V0.2 MCP Gateway Enforcement

V0.2 is the first hard security boundary.

Flow: MCP client -> IntentGuard MCP Gateway -> protected MCP server/tool -> resource.

The gateway binds an MCP request to an existing agent session/task, resolves the registered tool manifest, evaluates deterministic policy, and invokes a protected tool only after ALLOW.

Security invariant: DENY means zero downstream execution.

Implemented:
- /mcp JSON-RPC endpoint
- initialize, ping, tools/list, tools/call
- MCP session header binding
- registered tool/server manifest
- protected demo read_file tool
- deterministic policy before execution
- activity recording
- unknown-tool fail-closed behavior
- unit proof that DENY produces zero downstream execution

Current MCP documentation defines tools/list for tool discovery and tools/call for invocation. This implementation uses that standard vocabulary.

Not yet implemented:
- capability issuance/rotation/revocation
- provenance enforcement
- approval/quarantine
- risk scoring
- real IDE/agent deployment
- full MCP conformance certification

Next gate: add an end-to-end HTTP test proving a denied /mcp tools/call never reaches the protected handler.
