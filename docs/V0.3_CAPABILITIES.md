# V0.3 Capability-Based Authorization & MCP Gateway Integration

V0.3 implements cryptographic, task-scoped capability authorization enforced fail-closed at the MCP Gateway, accompanied by an authenticated control-plane lifecycle API for capability issuance, rotation, and revocation.

## Architecture & Security Invariant

Flow:
```
Operator / Control Plane
  → Authenticated API (/api/v1/control-plane/capabilities)
      [Auth: X-IntentGuard-Operator-Key & X-Operator-Id]
      [Validation: Task status, tool permission, resource scope, TTL bounds]
      → Issues unforgeable cryptographic token (only SHA-256 hash persisted)

AI Agent / MCP Client (with Mcp-Session-Id & X-IntentGuard-Capability)
  → IntentGuard MCP Gateway (/mcp)
      [Gate 1: Session Status Check]
      [Gate 2: Capability Validation BEFORE tool lookup]
      [Gate 3: Tool Manifest Lookup]
      [Gate 4: Deterministic Policy Engine Evaluation]
  → Protected Tool Execution
  → Target Resource
```

**Security Invariant:** Missing, invalid, expired, revoked, rotated-away, or out-of-scope capabilities are denied immediately with zero downstream tool lookup and zero execution.

## MCP Protocol Endpoint

- **URL:** `POST http://localhost:8080/mcp`
- **Supported Methods:**
  - `initialize`: Returns gateway server info (`intentguard-mcp-gateway` v0.3.0) and supported capabilities.
  - `ping`: Standard health ping returning `{}`.
  - `tools/list`: Returns all enabled tool manifests from `mcp_tool_manifests`.
  - `tools/call`: Executes a protected tool subject to capability and policy validation.

### Required MCP Headers
- `Mcp-Session-Id`: Active agent session ID bound to an active task.
- `X-IntentGuard-Capability`: Cryptographic capability token authorized for task, tool, and resource scope.
- `Mcp-Protocol-Version`: Protocol negotiation header (optional).

## Control-Plane API (Capability Lifecycle)

All control-plane endpoints require authenticated operator credentials:
- `X-IntentGuard-Operator-Key`: Shared operator secret configured via `intentguard.control-plane.api-key`.
- `X-Operator-Id`: Identity of the operator/service requesting capability operations. Must match the task's `actor_id` (or system/admin).

### 1. Issue Capability
- **Endpoint:** `POST /api/v1/control-plane/capabilities`
- **Headers:** `X-IntentGuard-Operator-Key`, `X-Operator-Id`
- **Request Body:**
  ```json
  {
    "taskId": "T-1",
    "toolName": "read_file",
    "resourceScope": "workspace/src/*",
    "ttlSeconds": 3600
  }
  ```
- **Response:** `201 Created`
  ```json
  {
    "capabilityId": "CAP-...",
    "taskId": "T-1",
    "toolName": "read_file",
    "resourceScope": "workspace/src/*",
    "status": "ACTIVE",
    "issuedAt": "2026-10-07T12:00:00Z",
    "expiresAt": "2026-10-07T13:00:00Z",
    "token": "<unforgeable-raw-token>"
  }
  ```
- **Security Invariant:** The raw token is returned **only once** at issuance time. Only its SHA-256 hash is persisted in MySQL (`capabilities.token_hash`). Raw tokens are never logged or persisted.

### 2. Rotate Capability
- **Endpoint:** `POST /api/v1/control-plane/capabilities/{capabilityId}/rotate`
- **Headers:** `X-IntentGuard-Operator-Key`, `X-Operator-Id`
- **Request Body:** `{"ttlSeconds": 3600}` (optional)
- **Response:** `200 OK`
  ```json
  {
    "capabilityId": "CAP-NEW-...",
    "rotatedFromId": "CAP-OLD-...",
    "taskId": "T-1",
    "toolName": "read_file",
    "resourceScope": "workspace/src/*",
    "status": "ACTIVE",
    "issuedAt": "2026-10-07T12:30:00Z",
    "expiresAt": "2026-10-07T13:30:00Z",
    "token": "<new-unforgeable-raw-token>"
  }
  ```
- **Behavior:** The previous capability is immediately marked `REVOKED` in the database. Any subsequent MCP tool call using the old raw token is denied with `CAPABILITY_REVOKED`. The replacement token is returned once for immediate client rotation.

### 3. Revoke Capability
- **Endpoint:** `POST /api/v1/control-plane/capabilities/{capabilityId}/revoke`
- **Headers:** `X-IntentGuard-Operator-Key`, `X-Operator-Id`
- **Response:** `200 OK`
  ```json
  {
    "capabilityId": "CAP-...",
    "status": "REVOKED",
    "revokedAt": "2026-10-07T12:35:00Z"
  }
  ```

### 4. Query Capability Metadata
- **Endpoints:**
  - `GET /api/v1/control-plane/capabilities/{capabilityId}`
  - `GET /api/v1/control-plane/capabilities?taskId={taskId}`
- **Headers:** `X-IntentGuard-Operator-Key`, `X-Operator-Id`
- **Response:** Capability metadata including ID, task, tool, scope, status, timestamps. **Never exposes raw tokens or hashes.**

## Capability Enforcement Matrix

| Condition | Gateway Result | Downstream Tool Executed? |
|---|---|---|
| Valid token, matching task/tool/scope, active, unexpired | `ALLOW` → passes to policy engine | Yes (if policy allows) |
| Missing token header | `DENY` (`CAPABILITY_REQUIRED`) | No |
| Unknown / tampered token | `DENY` (`INVALID_CAPABILITY`) | No |
| Task mismatch | `DENY` (`CAPABILITY_TASK_MISMATCH`) | No |
| Tool mismatch | `DENY` (`CAPABILITY_TOOL_MISMATCH`) | No |
| Revoked token | `DENY` (`CAPABILITY_REVOKED`) | No |
| Rotated (old) token | `DENY` (`CAPABILITY_REVOKED`) | No |
| Expired token | `DENY` (`CAPABILITY_EXPIRED`) | No |
| Target outside resource scope | `DENY` (`CAPABILITY_SCOPE_DENIED`) | No |
| Inactive / terminated session | `DENY` (`INACTIVE_SESSION`) | No |
